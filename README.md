# Sound Engineer — portfolio

Минималистичный одностраничный сайт для sound engineer'а (mixing & mastering).
Чистый HTML/CSS/JS, без сборки и зависимостей.

```
index.html
css/style.css
js/main.js
assets/img/      фотографии
```

Аудио и обложки треков не лежат в репозитории — они тянутся напрямую
с CDN Apple (см. раздел «Аудио»).

## Запуск

Любой статический сервер (нужен именно http:// — из `file://` не построятся
реальные waveform'ы, они подменятся на сгенерированные):

```bash
python3 -m http.server 8000
```

## Что менять под себя

| Что | Где |
|---|---|
| Имя, тексты, проекты, услуги, цены | `index.html` |

### Фото

Сейчас стоят снимки с Unsplash (свободная лицензия) как плейсхолдеры.
Замените на свои — сохраните те же имена файлов, и ничего править не придётся.
Все изображения обесцвечиваются через CSS-фильтр, так что цвет исходника не важен.

- `portrait.jpg` — **своё** фото студии (hero), квадрат
- `studio-desk.jpg` — блок About
- `desk.jpg`, `rack.jpg`, `board.jpg`, `laptop.jpg` — плейсхолдеры Unsplash,
  остались только как превью для строк без обложки

### Аудио и кредиты

Список работ и аудио взяты с публичного профиля на
[Muso.AI](https://credits.muso.ai/profile/5a71f47b-1722-4e92-a587-620e8ef352de/credits)
(сортировка по популярности). Все **265** позиций: топ-30 зашиты в разметку
`index.html` (у них проверенные жанры для фильтра), остальные 235 лежат в
`js/credits-extra.js` и строятся в DOM при загрузке — скрыты кнопкой
«Show all 265». У доп. треков жанр не проверялся, поэтому в жанровых
фильтрах они не участвуют — видны только под «All».

Как обновить список — данные не запрашиваются с сайта в рантайме, они
вшиты в разметку. Чтобы обновить, откройте страницу профиля в браузере
и выполните в консоли:

```js
const f = window.__NUXT__.fetch['ProfileCredits:0'];
copy(f.credits.map(c => ({
  track:   c.track.title,
  artists: c.artists.map(a => a.name).join(', '),
  roles:   c.credits.join(' · '),
  date:    c.releaseDate,
  preview: c.track.previewUrl,               // p.scdn.co mp3
  spotify: c.track.spotifyId,
  art:     c.album.avatarUrl_640_640,        // обложка релиза
})));
```

Nuxt отдаёт кредиты через SSR — они лежат прямо в `window.__NUXT__`,
отдельного публичного API у Muso.AI нет (`api2.muso.ai` закрыт
Cloudflare-челленджем). Другие страницы: `?page=2…9`.

В разметке из этого нужны:
- `data-src` — mp3-превью (30 сек), CDN Spotify отдаёт
  `Access-Control-Allow-Origin: *`
- `data-img` — обложка релиза (превью под курсором)
- ссылка `↗` на `https://open.spotify.com/track/{spotifyId}`

Waveform строится из настоящего mp3 через Web Audio; если файл
недоступен — рисуется детерминированная форма-заглушка, интерфейс
не ломается.

Если появятся собственные mp3 — положите их в `assets/audio/` и укажите
локальный путь в `data-src`, остальное менять не нужно.

> Превью живут на CDN Spotify. Если ссылка когда-нибудь протухнет,
> плеер не сломается — просто нарисует заглушку вместо волны.

### Формы

Три точки входа, два разных транспорта — потому что форме дистрибуции нужно
вложение, а вложения у Web3Forms платные.

| Форма | Куда шлёт |
|---|---|
| Заявка в секции Contact, «Book now» на карточках услуг | Web3Forms |
| Дистрибуция | своя функция `api/distro.js` → [Resend](https://resend.com) |

**Заявки** — POST на `https://api.web3forms.com/submit`, ключ лежит прямо в
`js/main.js` (`FORM_ACCESS_KEY`). Так и задумано: ключ рассчитан на клиентский
код и ничего, кроме приёма формы, не открывает. Если запрос не прошёл — откат
на `mailto:`, форма не ломается.

**Дистрибуция** — multipart на `/api/distro`, которая складывает письмо и
прикладывает обложку. Две реализации с одинаковым JSON-контрактом:

- `api/distro.js` — Edge-функция на Vercel, читает `RESEND_API_KEY` из
  переменной окружения проекта
- `api/distro.php` — порт того же кода для хостов без постоянного Node
  (например IONOS shared hosting); ключ лежит в `distro-config.php` **вне**
  докрута (см. `distro-config.example.php`), `.htaccess` в корне
  прозрачно переписывает `/api/distro` → `api/distro.php`, так что
  `js/main.js` не завязан на конкретный хостинг

`mstpd.com` подтверждён в Resend, поэтому `MAIL_FROM` шлёт с
`mail@mstpd.com` — можно отправлять на любой адрес, а не только на
почту владельца Resend-аккаунта, как было бы с общим
`onboarding@resend.dev`.

Здесь отката на `mailto:` нет намеренно: он не умеет прикладывать файлы и
обложка потерялась бы молча — вместо этого форма честно сообщает об ошибке.

Обложка не проверяется по содержанию: принимается любое изображение,
любых пропорций и размера. Раньше блокировались не-JPEG/PNG, непрямоугольные
и меньше 3000×3000 — эти правила сняты, требования площадок остались только
подсказкой под полем. Размеры файла показываются в подписи, но ни на что не
влияют.

Единственное, что осталось, — потолок в 4 МБ: это не про качество обложки,
а про лимит на размер запроса у Vercel. Проверяется и в браузере, и в обеих
функциях.

Аудио трека прикрепляется файлом и приходит вложением. Браузер читает
заголовок самого WAV (обходя чанки — `JUNK`/`LIST` перед `fmt ` встречаются
часто) и сверяет разрядность и частоту, так что 32-бит или 96 кГц
отсекаются до отправки, с указанием, что именно в файле не так.

Потолок — 28 МБ, и он продиктован почтой: Resend принимает 40 МБ на письмо,
но **после** base64, который раздувает файл на треть. Одна и та же цифра
стоит в браузере и в обоих бэкендах.

> Загрузка трека работает только на PHP-хосте (`api/distro.php`), где
> потолок — это `post_max_size` / `upload_max_filesize` сервера. У Vercel
> лимит тела запроса 4.5 МБ на любом тарифе, и он платформенный: файл
> отклоняется раньше, чем функция запустится. То есть на mstpd.com форма
> принимает трек, на превью-копии Vercel — нет. Если на IONOS отправка
> с треком возвращает ошибку, первым делом смотреть эти два значения PHP:
> при превышении PHP отбрасывает загрузку молча, поэтому `distro.php`
> проверяет `UPLOAD_ERR_INI_SIZE` и сообщает об этом явно, а не шлёт
> письмо без трека.
>
> Если нужны файлы больше — это уже отдельное хранилище (Vercel Blob или
> загрузка на диск с отдачей ссылки), а не правка формы.

Защита от ботов на всех формах — скрытое поле `botcheck` (honeypot).

## Что внутри

- мобильный плеер в духе Apple Music: мини-бар внизу + полноэкранная
  панель (обложка, размытый фон из неё же, скраббер, prev/play/next,
  свайп вниз для закрытия, автопереход на следующий трек). Появляется
  только на ширине ≤900px, на десктопе остаются waveform-плееры
- фикс-навигация с blur-фоном и подсветкой активной секции
- hero: маска-раскрытие заголовка, zoom-out фото, parallax по object-position
- reveal-анимации по скроллу (IntersectionObserver, со стаггером)
- плеер: canvas-waveform, клик = перемотка, одновременно играет только один трек
- список релизов: миниатюра, следующая за курсором (desktop)
- полностью адаптивно; уважает `prefers-reduced-motion`
